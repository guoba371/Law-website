# 律所站群营销工作台

## 代码结构

按「前台 / 后台 / 服务端 / 共用」四块划分，看到目录就知道文件属于哪一边。

```
src/
├─ pages/                 路由。Astro 规定页面必须放在这里，无法移动。
│  ├─ admin/              后台路由
│  └─ 其余文件             前台路由
├─ site/                  前台实现
│  ├─ components/         页头、页脚、咨询条、主题开关
│  ├─ layouts/            SiteLayout
│  └─ styles/site.css     前台版式
├─ admin/                 后台实现
│  ├─ components/         文章编辑器
│  ├─ layouts/            AdminLayout
│  └─ styles/admin.css    后台版式
├─ shared/                前后台共用
│  ├─ base.css            品牌变量、reset、焦点样式、按钮
│  └─ content.css         文章正文排版
├─ server/                只在 Node 端运行，浏览器拿不到
│  ├─ db.ts               数据库连接与建表
│  ├─ store.ts            所有数据读写都走这里
│  ├─ auth.ts             登录与会话
│  ├─ media.ts            图片上传、读取、删除
│  ├─ article-form.ts     文章表单校验
│  └─ site-url.ts         生成前台绝对地址
├─ content/firm.ts        内容源数据（种子）
├─ middleware.ts          鉴权与上传兜底，Astro 规定放在这里
└─ env.d.ts
```

仓库根目录：

- `data/` — 运行时的全部状态：`app.db` 数据库 + `uploads/` 图片。**迁移时只需要复制这一个目录**
- `dist/` — 构建产物。`client/` 是纯静态站点，`server/` 是后台进程入口
- `deploy/nginx.conf.example` — 部署配置示例
- `docs/system-design-spec.md` — 系统设计规格
- `scripts/copy-uploads.mjs` — 构建时把上传目录同步进静态产物

**两条边界规则**：所有数据访问收在 `server/store.ts`，页面里不写 SQL；样式只有 `shared/base.css` 里的 `:root` 定义颜色，改配色只改那一处。

## 运行

```bash
npm install
npm run dev      # 开发模式，前台改动即时可见
npm run build    # 生成静态站点（dist/client）+ 服务端入口（dist/server）

```

## 设计系统

按 design-taste 技能建立，改样式前先读 `src/shared/base.css` 顶部的注释。

**Design read**：信任优先的专业服务站点，受众是有真实纠纷的当事人。语言取向是克制的文书感。

**Dials**：`DESIGN_VARIANCE 4` / `MOTION_INTENSITY 3` / `VISUAL_DENSITY 5`。对应技能里「trust-first / regulated」档位，不是默认基线。动效只做 hover、focus 与 active 反馈，不做滚动动画。

**三条锁定规则**：

1. 形状锁：全局统一 2px 圆角，不出现 pill 按钮或大圆角卡片。
2. 颜色锁：唯一强调色是黄铜色 `--brass`。用于线条，`--brass-ink` 用于文字以保证对比度。
3. 字体锁：无衬线承担界面与标题，衬线只用于法律条文、引文和律所字标。

**字体策略**：全部使用系统中文字体栈，不加载 Web Font。原因是中文 Web Font 体积大，且国内 CDN 不稳定。显示字体走 `PingFang SC / Microsoft YaHei / Noto Sans SC`，在 Windows、macOS、Android 上都有可用回退。标题改用无衬线而非宋体，是因为 Windows 的宋体回退（SimSun）在大字号下笔画过细，会直接毁掉专业感；衬线保留给法条和引文，那是它的原生尺寸。

**配色与主题**：全部颜色走 CSS 变量，切换主题只替换 token，不改结构。已实测两套配色的对比度，正文 17.2:1 / 14.9:1，次要文字最低 4.75:1，均通过 WCAG AA。

**深浅切换**：页头右上角有手动开关，图标显示的是将要切换到的模式（浅色下显示月亮，深色下显示太阳）。

- 首次访问跟随系统偏好，用户手动选择后写入 `localStorage` 并长期保留
- 判断与写入分两处：`SiteLayout.astro` 里的内联脚本在首屏绘制前设置 `<html data-theme>`，避免刷新时闪烁；`ThemeToggle.astro` 负责按钮状态、图标与 `theme-color` 同步
- 深色主题由 `:root[data-theme="dark"]` 驱动，不由 `prefers-color-scheme` 驱动。两者并存会有两个事实来源，改配色时要改两处，所以只保留属性选择器
- 关闭 JavaScript 时页面固定为浅色，内容与功能不受影响
- 窄屏（< 720px）下隐藏页头的「预约咨询」按钮给开关让位，该入口保留在顶部信息条和展开菜单里

**首屏规则**：文本元素不超过 4 个（标题、说明、两个按钮），执业数据带移到首屏下方，不放在首屏内。标题在 1440px 下不超过 2 行。

## 设计验收时有意避开的模式

以下都是大模型生成页面的典型特征，本项目明确不用：

- 每个 section 上方都挂一个小标签（eyebrow）。全站只有 0 处
- 三等分功能卡片。律师展示改为带分隔线的名录行，首位律师加重
- 步骤编号（`01 / 02 / 03`）。流程用有序列表语义加分隔线，不印数字
- 长列表每行都加 `border-top` 和 `border-bottom`。只保留一个方向的分隔线
- 纯白 `#ffffff` 与纯黑 `#000000`。改用 `#fdfcfa` 与 `#12161c`
- 破折号（`—` / `–`）作为排版装饰。全站零使用，构建产物已校验
- 假的精确数字。首屏数据带只放可核对的事实（成立年份、律师人数、办公地、业务方向），不放累计办案量这类需要举证的数字

### 咨询表单与通知

前台联系页有在线咨询表单，收集姓名、电话、邮箱、咨询类型和内容。提交后写入 `inquiries` 表，同时推送到钉钉群机器人和邮箱。两道保护：隐藏字段防机器人，同一 IP 十分钟限流一次。

表单带隐私政策勾选，隐私政策页在 `/privacy/`。通知渠道通过环境变量配置，不配置就静默跳过，不影响表单本身。

### 多站点

数据模型已经带站点维度：`sites` 表 + 文章和咨询线索的 `site_id` + 按站点隔离的设置。后台右上角会显示站点切换器（只有超过一个站点时出现），文章编辑器和设置页都会按当前站点读写。

前台目前渲染一个站点，由构建时的 `SITE_ID` 决定，默认是主站（id=1）。站群渲染上线时，每个站点各构建一次并传入自己的 `SITE_ID`。

### 文章配图

编辑器正文上方有「插入图片」按钮，支持一次选多张。上传后按 Markdown 图片语法插到光标位置，并且自动选中方括号里的「图片说明」占位文字，直接打字就能替换成描述画面内容的句子（搜索引擎会读它）。

正文下方会列出这篇文章用到的所有图片，每张有两个操作：

- 「移除引用」只把图片从正文删掉，文件留在服务器上备用
- 「删除文件」会同时从正文移除并删除文件，删除前有二次确认

被其他文章或站点 Logo 引用的文件不允许删除，服务端会拒绝并列出引用来源。删除校验会带上编辑器里未保存的正文，所以不需要先保存再删。

配图格式限 PNG、JPG、WebP，单张不超过 5MB。**不收 SVG**：SVG 能在同源下执行脚本，正文图片上传次数多，风险面比 Logo 大。站点 Logo 仍允许 SVG。

### 正文编辑器

左边写作、右边实时预览，用同一个 `marked` 渲染，预览和前台结果一致。两栏滚动按比例同步，窄屏（< 900px）自动改为上下堆叠并停用同步。

工具栏按钮对光标所在段落生效，再点一次取消：

| 按钮 | 作用 |
|---|---|
| 标题 / 小标题 | 加二级、三级标题，切换式 |
| 加粗 | 选中文字加粗；没选中则插入占位文字并选中 |
| 项目符号 / 编号列表 | 对选中的多行加列表标记，编号自动递增 |
| 法条引文 | 加引文块，前台渲染成左侧黄铜竖线的衬线排版 |
| 链接 | 有选中内容就作为链接文字，光标落在地址上 |
| 插入图片 | 上传后插入 Markdown，并选中图片说明占位 |

快捷键：`Ctrl/Cmd + B` 加粗，`Ctrl/Cmd + K` 插入链接。

标题、列表、引文互斥，应用新标记前会清掉旧的，不会出现 `1. > 文字` 这种叠加结果。

### 数据与生效方式

- 数据存 SQLite，文件是 `data/app.db`，用 Node 内置的 `node:sqlite`，没有原生依赖
- 首次运行自动建库，并从 `src/content/firm.ts` 写入种子数据。之后以数据库为准
- 公开页面是预渲染的，所以后台的改动需要点一次「重新构建站点」才会出现在前台，构建约 2 秒
- 业务领域、律师、城市、地域页仍来自 `src/content/firm.ts`，后台只读展示，尚未开放编辑

### 架构

`output: static` 加 `@astrojs/node` 适配器。公开路由全部静态预渲染，`/admin` 下的路由标记 `prerender = false` 按需渲染。生产部署时把 `dist/client` 推到 OSS/CDN，后台单独跑 `dist/server/entry.mjs`。

### 安全

- 会话是 HMAC 签名的 HttpOnly Cookie，有效期 12 小时，密钥首次运行生成并入库
- 密码比对使用定长时间比较
- 后台路由带 `noindex, nofollow`，`robots.txt` 禁止抓取 `/admin/`，站点地图已排除后台路径
- Astro 默认对按需渲染路由开启 Origin 校验，跨站表单提交会被拒绝（实测返回 403）
- 已知限制：Markdown 正文未做 HTML 消毒。当前是单管理员可信场景，开放多人编辑前必须补上

### 一个必须知道的浏览器坑

编辑站点设置时，Chromium 的自动填充启发式会按输入框的 `id`、`name`、`type` 匹配 `phone` 与 `email`，命中后**直接剥离 `value` 属性**，导致保存时把电话和邮箱写成空值。`autocomplete="off"` 拦不住，实测无效。

所以设置表单里这两个字段的表单名与数据库键名是分开的：`phone` 提交为 `contactDial`，`phoneDisplay` 为 `contactDialShown`，`email` 为 `contactInbox`，且都不用 `type="email"`。改动这部分时不要把它们改回语义名。

## 部署到公网

### 怎么进入后台

后台地址是 `你的域名/admin/`，例如本地是 http://localhost:4321/admin/ 。

**前台不放任何进入后台的链接**，这是有意的：律所官网的页脚出现「后台管理」对客户是减分项，而且把入口藏起来并不提升安全性，地址本身是可猜的，扫描器一定会扫 `/admin/`。真正的防线是密码强度加 HTTPS，所以进入方式就是存一个书签。

如果用了独立子域名，访问 `admin.你的域名/` 会被跳到 `admin.你的域名/admin/`（Nginx 里配了一条 302）。

会话 cookie 只在 `/admin` 路径下发送，前台页面和图片请求都不会带上它。后台页面响应带 `no-store`，退出登录后按浏览器后退键看不到缓存内容。

> 已知限制：会话是无状态的 HMAC 签名令牌，服务端不记录已签发的令牌。所以「退出登录」只清除浏览器上的 cookie，那个令牌在 12 小时有效期内仍然可用。单管理员场景风险很低，但如果将来要开放多人账号，需要改成服务端会话表（登录时入库、退出时删除、每次请求校验存在性）。

### 站点状态只有一个目录

`data/` 装着全部可变状态：`app.db` 是 SQLite 数据库（文章、站点设置、会话密钥），`uploads/` 是上传的图片。**迁移站点就是复制这一个目录**，代码不用动。

备份和迁移前先停掉服务，因为 SQLite 开了 WAL，运行中复制可能拿到不完整的数据：

```bash
# 停服务后
tar -czf law-site-backup.tar.gz data/        # 备份
# 换机器：装好代码，把 data/ 放回项目根目录，npm run build && npm start
```

### 环境变量

复制 `.env.example` 为 `.env`，或直接在 shell 里传。构建期和运行期都会读 `.env`。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SITE_URL` | `https://example.com` | 站点对外地址。影响 canonical、og:url、站点地图、robots.txt。**改完必须重新构建** |
| `ADMIN_PASSWORD` | `lawfirm2026` | 后台密码。上线前必须改 |
| `SITE_ID` | `1` | 前台当前渲染的站点 ID，站群上线时每个站点构建一次 |
| `DINGTALK_WEBHOOK` / `DINGTALK_SECRET` | 空 | 钉钉群机器人通知。不配置就不发钉钉 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` / `SMTP_USER` / `SMTP_PASS` / `NOTIFY_EMAIL` | 空 | 邮件通知，用国内企业邮箱的 SMTP。不配置就不发邮件 |
| `PORT` | `4321` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |

改密码或域名后要重启服务；改域名还要重新 `npm run build`。

### 服务器要求

- **Node 24 或更高**。数据库用的是 Node 内置的 `node:sqlite`，没有原生编译依赖，但低版本 Node 不支持
- 生产部署要装完整依赖（含 devDependencies），因为后台的「重新构建站点」按钮需要调用 `astro build`
- `data/` 和 `dist/` 两个目录都要可写

### 两种部署方式

Nginx 配置示例在 `deploy/nginx.conf.example`，两种拓扑都写好了，按备案情况选一种。里面有两个容易踩的坑已经配好：`client_max_body_size` 必须放开（Nginx 默认 1MB，会在上传 5MB 图片时返回 413），以及 `X-Forwarded-Proto` 必须传给应用（否则会话 cookie 拿不到 `Secure` 标记）。

**单进程（推荐，最省事）**

```bash
npm ci
SITE_URL=https://www.你的域名.com npm run build
npm start          # 前台和后台都在同一个进程里
```

前面挂 Nginx 做 HTTPS 和域名。上传的图片由进程自己响应，改完立刻生效。

**静态产物推 CDN，后台单独跑**

`npm run build` 会把 `data/uploads` 同步进 `dist/client/uploads`，所以 `dist/client` 是一个完整可推的静态站点。后台进程单独跑 `dist/server/entry.mjs`，Nginx 把 `/admin/` 和 `/uploads/` 转发过去即可。

注意这种方式下，每次在后台点「重新构建站点」后都要重新同步一次 `dist/client` 到 CDN，否则图片和静态页面不会更新。
